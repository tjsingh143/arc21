Last reviewed: **2026-09-02 (phase 9).** No asset was added, removed or changed
in that review; two references to where the cosmetic catalogue lives were

Every external asset shipped in this application must be recorded here with its
source and license **before** it is committed. An asset with no entry in this
file is a release blocker.

## Intellectual property policy

Arc 21 is an original product. It must not copy another game's source code,
screenshots, screen layouts, logo, name, character art, card backs or marketing
copy, and must not trace another game's assets.

"Arc 21" is a **temporary development codename**. It has not been
trademark-cleared and must be marked as such until naming review occurs.

## Current inventory

**No third-party asset is present in the repository.** Everything shipped is
generated by code in this repository. The binary content is the sound palette
and the two app-art PNGs; every other visual, including all 24 cosmetics, is
source code.

### Audio — all originally generated

Nine cues in `assets/audio/`, each synthesised from oscillators, envelopes and
filtered noise written in `scripts/generate-audio.ts`. Nothing is sampled,
downloaded, bought, borrowed or traced. There is no third-party licence to record
because there is no third-party content.

Regenerate with:

```bash
npm run audio:generate
```

The output is **deterministic** — the noise source is a seeded LCG rather than
`Math.random` — so regenerating produces byte-identical files, and
`tests/audio/generated-audio.test.ts` re-synthesises every cue and compares it
with the committed file. A diff therefore means somebody changed the recipe, not
that a build machine differed.

All nine are 16-bit mono PCM at 22,050 Hz. **103 KiB in total** — measured in the
iOS export, where all nine appear as bundled assets alongside 23 PNGs belonging
to `expo-router`.

The peak column is not decoration. A loss is quieter than a win, a win is quieter
than a blackjack, and the two cues that repeat most often — the card and the chip
— are the quietest of all. That ordering is asserted in `tests/audio`, because
"restrained" is otherwise a matter of opinion.

**No music ships.** The specification allows one understated ambient loop
defaulting to off; absent and off are the same thing to a player, with less to go
wrong. The Settings row says so rather than offering a switch that controls
nothing.

### App icon and splash — originally generated

Two PNGs in `assets/images/`, both written by `scripts/generate-app-art.ts`: a
signed-distance rasteriser over capsule strokes and ring segments — a compass
and a straight edge, in code. The mark is an arch over the numerals 21 in the
accent ink on the app background. Deliberately not a card, a chip or an ace.

Regenerate with:

```bash
npm run art:generate
```

The output is **deterministic** — pure arithmetic, no randomness — and
`tests/art/generated-app-art.test.ts` regenerates both images and compares them
byte for byte with the committed files, exactly as the audio test does.

### Cosmetics — 24 SVG components

Every avatar, card back and table theme in the catalogue is a
`react-native-svg` component in this repository. The source paths below identify
the geometry used by each asset:

| Kind | Count | Source | License |
|------|-------|--------|---------|
| Avatars | 12 | `src/features/cosmetics/art/avatars.tsx` | Original work, © Arc 21 |
| Card backs | 8 | `src/features/cosmetics/art/card-backs.tsx` | Original work, © Arc 21 |
| Table themes | 4 | `src/features/cosmetics/art/table-themes.tsx` | Original work, © Arc 21 |

Those counts are the specification's minimum ("at least 12 avatar variants, 8
card backs, 4 table themes") and are met exactly. Every one is earned by
playing — a level, a career node, a chapter, a daily streak or a tournament
placement — and `cosmetic_unlock_type` has no member that could express a
purchase or a random draw, so adding one would take a migration and a deliberate
decision rather than an INSERT.

Flat vector geometry throughout: two or three colours per asset from the design
tokens (plus the cosmetic surface tones recorded in `src/design/tokens.ts`),
hard edges, no gradient meshes, no bevels, no photorealism. Avatars are
abstract geometric marks, not faces or characters. Card backs are built from
primitives in this repository and resemble no other game's backs. Table themes
are a flat tone plus at most one hairline element — no felt texture. Suit
identity on cards never depends on colour, and no card back changes that.

`tests/cosmetics/registry.test.ts` parses the catalogue out of the migration
that writes it — `supabase/migrations/20260823110000_catalogue_ships_in_migrations.sql`
— and asserts every `asset_key` resolves to one of these components with no
orphans in either direction, so nothing can be added to the catalogue without an
original drawing landing here beside it. It also asserts the CATALOGUE SIZE
(12 / 8 / 4), which is what catches a regex that has stopped matching rather
than a catalogue that has stopped growing.

The source moved out of `supabase/seed.sql` and into a migration because the
seed does not run on `supabase db push`, so a deployed project would have had no
cosmetics at all. This paragraph named the seed file for a while after the test
had already been repointed; the file the test reads is the one above.

## Planned asset strategy

The specification requires original assets. The intended approach, none of which
introduces third-party artwork:

### Playing cards
Rendered **programmatically** — rank, suit glyph, centre pip treatment, and an
accessible text label. No card image files, which also keeps the bundle small and
scales cleanly to any density.

Suit identity must never depend on colour alone: every card carries a glyph and
an accessible name, so red/black is never the only distinction.

### Card backs
**Done** — see the cosmetics inventory above. Original patterns built from SVG
geometric primitives, with a distinct composition for each card back.

### Avatars
**Done** — abstract geometric marks on a shared grid, deliberately NOT
characters or faces; distinct at 32 px by silhouette rather than by detail.

### Table themes
**Done** — a flat surface tone plus at most one hairline element each. **No
literal green felt**: "Arc Green" is a desaturated surface green, not baize.

### App icon and splash
**Done** — see the inventory above. Generated by `scripts/generate-app-art.ts`; no icon library was
adopted, so there is no third-party licence to record.

### Fonts
System fonts initially, for speed and correct platform rendering. Any custom face
added later must be license-cleared and recorded here.

### Audio
**Done** — see the inventory above. Generated rather than recorded or licensed,
which was chosen precisely because it is the one form of "original" that anybody
with the repository can re-derive and audit.

No casino crowd noise, no slot jingles, no continuously raining coins, and no
music at all.

## Adding an asset

1. Confirm the license permits commercial redistribution in a mobile app.
2. Add a row to the inventory table above: file path, type, source URL, license
   (SPDX identifier where one exists), and attribution requirements.
3. If attribution is required, ensure it appears in Settings → About.
4. Keep the original license text in `assets/licenses/` alongside the asset.
