# Arc 21 repository map

Arc 21 is a portrait-phone blackjack game using virtual chips with no monetary
value. Inspect the working tree and relevant production callers before editing;
verify behavior through the running app and backend, not just helper tests.

## Architecture and sources of truth

- `app/`: Expo Router screens. `src/components/` and `src/design/`: shared UI,
  accessibility, typography, and visual tokens. `src/features/`: Zustand stores
  and gateways. `src/lib/`: Supabase, persistence, connectivity, audio, and push.
- `shared/blackjack/`: the single runtime-neutral engine. `rules.ts` defines
  Arc Standard: six decks, S17, peek, 3:2, late surrender, DAS, four split hands,
  and one-card split aces. `public-state.ts` is the hidden-card boundary.
- `shared/contracts/`: strict request/response schemas. Client commands carry
  intent, an idempotency key, and an expected version; never trusted cards,
  identity, balances, scores, or results.
- `supabase/functions/create-session/`, `game-command/`, and
  `send-notifications/`: production Edge Functions. `_shared/` owns server
  persistence, settlement, competition boundaries, and secret access (`env.ts`).
- `supabase/functions/_shared/strategy/` and `career/` contain canonical shared
  learning/progression logic; `shared/strategy/` and `shared/career/` re-export it.
  Strategy data is generated by `scripts/generate-strategy-tables.ts`.
- AI Tables (Refresh C): `supabase/functions/_shared/ai-seat-policy.ts` decides
  for a computer seat from an observation built ONLY from `toPublicState`;
  `ai-seat-driver.ts` runs those decisions inside the person's own command, through
  `assertCommandIsLegal` and `applyCommand`. Record: `docs/astra-refresh/refresh-c.md`.
- Home/Play hierarchy (Refresh D): `src/features/home/product-hierarchy.ts` is the
  one definition of the tiers (chip play → AI Tables → Practice and progress), each
  mode's entry route and its claims; both tabs render it, and the claims are tested
  against the server allowlists. Record: `docs/astra-refresh/refresh-d.md`.
- `supabase/migrations/` is the database/deployment authority, including product
  catalogues. `seed.sql` is not a substitute for deployable catalogue migrations.
- Product and accepted rule choices: `docs/BLACKJACK_RULES.md`,
  `docs/ARCHITECTURE.md`, `docs/DATABASE.md`, and `docs/SECURITY.md`.
  Current release index: `docs/LAUNCH_STATE.md`; verification and external
  activation requirements: `docs/astra-refresh/baseline-audit.md` and
  `docs/RELEASE.md`. Refresh B implementation/evidence: `docs/astra-refresh/refresh-b.md`. Phase reports and earlier checkpoints are historical evidence.

## Authority and invariants

- Every online player, including an unlinked pseudonymous player, has a verified
  Supabase Auth UUID. Internal `guest` mode means only the offline Practice
  fallback; never use it for Supabase anonymous users. Offline Practice owns
  only local practice state. Competitive Career,
  Daily, Sprint, public/private multiplayer, XP, cosmetics, and account wallets
  are server-authoritative. Never turn multiplayer into local simulated users.
- Production shuffles use `CryptoRandomSource`; seeded/preordered sources are
  for tests, except the server-secret deterministic Daily stream. Never expose
  future shoe order or an unrevealed hole card through responses or Realtime.
- Wallets begin with a 25,000-chip ledger grant. Every movement goes through
  `apply_wallet_delta` in the same transaction as its cause. Balance and ledger
  must reconcile; balances stay nonnegative; retries cannot debit/credit twice.
  Private stacks cannot enter the global wallet. See `session-economics.ts`.
- Handles are assigned atomically by the Auth INSERT trigger, filtered and
  unique. Securing uses verified email/password on the SAME UUID, never a
  second-account merge or local economic import. Preserve the optional recovery
  experience, destructive-loss warnings, atomic keychain storage, and player
  scope guards on late replies and economic retries.
- Identity comes from verified Auth, never payload metadata. All application
  tables use RLS; server-owned writes have narrow grants and write guards.
  `private` is inaccessible to client roles, including `service_role`.
- Computer players exist only at an `ai_table` (database trigger), never hold an
  account, never buy in, and are never authority: the engine does not read
  `isAi`. AI tables are a closed economy (no wallet in or out) and record no
  statistics, XP or accuracy. A migration is ONE transaction — a `commit; begin;`
  split is rolled back by the CLI after the `begin;`.
- Edge Functions use direct Postgres transactions for locks. Preserve the room
  → engine/seat lock order in multiplayer lifecycle operations. One live seat
  per account; departed seats/reservations must be released and reusable.
- Server versions and event sequences govern reconciliation. Retain one request
  ID per intent across response loss. A parsed rejection is a verdict, not a
  transport retry. Cash-out must finish before the table route is removed.
- Only public configuration may use `EXPO_PUBLIC_`. Secrets and local credentials
  stay untracked; consult `.env.example` for environment names.

## Verification and runtime

```sh
npm ci
npm run typecheck
npm run lint
npm run check:functions
npm run test:unit
npm run test:coverage
npm run contrast:check
npm run doctor
npm run bundle:check
npm run db:start # pins local PostgREST 16.3 before supabase start
supabase db reset --local
supabase test db
supabase functions serve --no-verify-jwt
npm run test:server
```

`--no-verify-jwt` disables the local gateway check; the functions still verify
JWTs. The required server script fails if the stack is absent. Unit coverage
does not measure code executing inside Docker. Tests live in `tests/`, SQL
authorization tests in `supabase/tests/`, and native flows in `tests/e2e/`.

For iOS, boot a named simulator, then build and install a fresh Release bundle:

```sh
LANG=en_US.UTF-8 npx expo prebuild --platform ios --clean
LANG=en_US.UTF-8 npx expo run:ios --configuration Release --device <UDID> --no-bundler
JAVA_HOME=/opt/homebrew/opt/openjdk maestro --device <UDID> test tests/e2e/<flow>.yaml
```

Native projects are generated and ignored; edit Expo configuration/plugins.
Release bundles inline environment values and run without Metro. Bundle Mode
needs generated worklets primed on a clean install (`bundle:check` handles it).
`check:functions` obtains Deno through npx and uses each function's import map.
Use `scripts/e2e-fresh-app.ts` for a fresh test install: Maestro `clearState`
does not erase iOS SQLite or Keychain. Fixture/cleanup scripts are local-only.
Avoid simultaneous native builds, simulator boots, and unconstrained test
workers on a memory-constrained host. After a database reset, re-serve functions
and verify both function and database reachability before interpreting failures.

Keep user changes and historical backups intact. Commit coherent local
checkpoints when requested. Do not push, deploy, or rewrite history without
authorization; check the actual branch/upstream rather than assuming they match.
