# Arc 21

A **simulated** blackjack game. Expo (iOS/Android) + Supabase. Virtual chips only.

Read `docs/IMPLEMENTATION_STATUS.md` for where the build actually is, and
`docs/AUDIT.md` for how strongly each area has been verified.

---

## Absolute invariants

These are not preferences. A change that violates one is wrong even if it passes.

1. **No outcome manipulation.** Cards are never influenced by losses, wins,
   wallet, level, purchases, retention or drama. If a requirement conflicts with
   this, reject it and write down why.
2. **No real money.** No wagering, cash-out, purchases, loot boxes, wheels,
   slots, side bets or paid advantage. Chips have no value and are
   non-transferable.
3. **Integer chips only.** No float ever touches a balance. Payouts are
   `floor(wager * num / den)` on integers.
4. **CSPRNG only in production.** `Math.random()` must never decide gameplay.
   The production RNG never falls back to the seeded test source.
5. **`toPublicState()` is the only sanitisation boundary.** Nothing else may
   build a client payload. Undealt cards and the unrevealed hole card never
   leave the server.
6. **Identity comes from the verified JWT.** Never trust a client-supplied
   userId, balance, seat, result, shuffle or placement.
7. **One engine.** `shared/blackjack` is runtime-neutral — no React Native, no
   Deno, no Node imports. Client, Edge Functions and tests all use it. Never
   write a second implementation of a rule.
8. **Never claim an external audit or certification.** None has happened.

Never log a password, token, hidden shoe, unrevealed hole card, challenge seed
or service credential.

## Architecture

- **Server authority:** transaction per command. Lock the row, check the
  idempotency key, check `expectedVersion`, apply the shared engine, move chips,
  bump version, append events, commit, then broadcast. No partial settlement.
- **Chips move only through `apply_wallet_delta`.** It locks the wallet row
  *before* honouring the idempotency key. Wallet writes are server-only; the
  ledger is append-only.
- **Escrow:** a buy-in debits the wallet once into a server-owned table stack;
  wagers move inside that stack; the remainder returns on safe close. The
  cash-out idempotency key is derived from `gameId:seatId`, not from a
  client-supplied id, so a fresh request id cannot buy a second credit.
- **Private engine state lives in the `private` schema** with no client grants.
- **Strategy tables are generated by the EV solver** in
  `scripts/generate-strategy-tables.ts`, never hand-typed, and keyed to
  `rulesetId@version`. The advisor returns `null` rather than guessing.
- **Reaching into `shared/` from `supabase/functions/` uses `.js` specifiers;
  everything WITHIN `supabase/functions` uses `.ts`.** Not a style choice: the
  first group is resolved by a per-function import map and the second from disk.
  See the resolution rules below before adding any import to a function.
- **Chips may only return to a wallet from a WALLET-BACKED mode.**
  `supabase/functions/_shared/session-economics.ts` is the single place that
  answers which: `solo` and `public_table` yes; `practice`, `private_table`,
  `tournament`, `daily_challenge` no. `settleTableClosure` reads the mode from
  the session row itself rather than taking it as an argument, because the
  consequence of a caller passing the wrong answer is minting chips — which is
  exactly what happened before it existed.
- **A seat closing and a TABLE closing are different events.** One player
  leaving a five-seat table must not end it for the other four.
  `settleTableClosure` returns `sessionEnded`, true only when no other connected
  seat remains.
- **A notification is server-written and carries deep-link parameters only.**
  `public.notify_user` is revoked from every client role, and
  `notifications.data` has a CHECK constraint allowing a fixed set of keys
  holding short scalars — so a seed, a shoe or a hole card cannot ride out
  through a push message even by accident. The sender records `mocked` rather
  than `sent` when no push credentials exist, and `sent_at` is stamped only by a
  real delivery.
- **Every sound is generated by `scripts/generate-audio.ts`**, deterministically,
  from oscillators and filtered noise written in this repository. Nothing is
  sampled, bought or borrowed, and `tests/audio` re-synthesises each cue and
  compares it byte for byte with the committed file.
- **Every rate limit is a row in `public.rate_limit_policies`**, read through
  `rate_limit_for(action)`. No enforcement point carries a window of its own, and
  `19_rate_limits.test.sql` asserts none does by pattern-matching the function
  bodies. Windows ROLL; a refusal is never itself recorded, or the window cannot
  drain and the limit becomes a ban. The limit is consumed BEFORE the target is
  looked at, so a refusal cannot differ by target and become a probe.
- **Competition shape lives in `_shared/session-boundary.ts`**, runs on
  `NEXT_HAND` before the engine deals, and is in the same transaction as the
  command. It changes posted bet limits, seating order and who is sitting out —
  never a card, a wager or an outcome.

### Edge-runtime module resolution — the actual mechanism

**Every function directory carries its own `deno.json` import map, and that map
is what makes a `shared/**` import resolve at all.**

Open `supabase/functions/game-command/deno.json`. It maps every `.js` specifier
to the `.ts` file it means:

```json
"../../../shared/contracts/index.js": "../../../shared/contracts/index.ts",
```

The three files are byte-identical, and `supabase/functions/deno.json` at the
root does **not** contain those entries — it holds only the npm aliases. Two
earlier versions of this note guessed at the cause from the symptoms ("new files
under `shared/` don't resolve", then "a specifier's depth matters"). Both were
descriptions of this one fact.

What follows from it:

1. **A NEW function directory MUST get a copy of that `deno.json`.** Without it
   the function cannot resolve `shared/contracts` or `shared/blackjack` —
   including transitively, which is the case that catches people:
   `_shared/command-errors.ts` imports the contracts, so a function that only
   imports the error helpers still needs the map.
2. **The failure takes the whole stack down, not just that function.** The edge
   runtime loads every function at startup, so an unresolvable import means
   `supabase start` reports
   `failed to read file: open shared/contracts/index.js` and exits with no
   Functions URL at all. Everything else keeps running, which makes it look like
   a database problem.
3. **Depth matters because the map keys are literal strings.**
   `../../../shared/blackjack/index.js` is a key; `../../../../shared/…` from a
   nested directory is not. `_shared/engine-primitives.ts` exists to re-export
   engine primitives at the depth the map covers.
4. **Inside `supabase/functions`, import with a literal `.ts` path.** Those
   specifiers are not in the map and are resolved from disk, where only `.ts`
   exists. Nested directories are fine.
5. The CLI also bind-mounts each `shared/**` file individually, visible in
   `docker inspect supabase_edge_runtime_arc21`. That is how the files get into
   the container; the import map is how a specifier finds them.

The consequence, and the pattern to copy: **code the server needs lives under
`supabase/functions/_shared/`, and `shared/` holds a one-line barrel that
re-exports it** for the client, the tests and the tooling. `shared/strategy` is
that shape — the advisor was MOVED, not copied, so there is still exactly one
implementation, and `npm run strategy:generate` writes into its new home. Where a
plain constant must genuinely be duplicated, add a test asserting the two are
equal — see `tests/progression/settlement-accounting.test.ts`.

### Deliberate deviations from the spec

- **Safety reserve is 52 cards, not 104.** At 6 decks a 104-card reserve makes
  the advertised 75% penetration impossible (it would trip first at 209 cards,
  giving ~67%). Penetration is a user-facing Fair Play claim, so the reserve
  gave way. `assertPenetrationIsCoherent()` enforces the relationship.

```bash
export PATH="/opt/homebrew/bin:$PATH"   # needed for supabase/docker/maestro

npx tsc --noEmit

```

maestro` installs an unrelated 682MB cask.

## Recurring mistakes

**"Tests pass" is not "it works."** The server layer typechecked with a green
suite while every command returned 500. Before claiming a feature is built, run
it against the real thing and paste the output. `docs/AUDIT.md` grades every
area by how it was verified for this reason.

**A skipped test is not a passing test.** `tests/server` skips without Docker.
Its guard requires a **401 from the function**: with the Edge runtime stopped
the gateway still answers 503, and an "any response" check reported the stack as
up while nine tests failed instead of skipping.

**`${json}::jsonb` double-encodes.** It stores a JSON *string*. Use
`::text::jsonb`. When this broke every command, the first fix — making the
parser tolerate strings — was wrong in kind: it papered over the write bug. A
CHECK constraint caught the fudge.

**Never call a Zustand getter during render.** The React Compiler memoises
against the stable function reference, freezing the value. This disabled the
Deal button permanently and was invisible to 378 passing tests. Subscribe to
state and `useMemo` on it.

**Maestro:** `id:` matches `testID`, not `accessibilityLabel` — they are
different things on iOS, and a label *replaces* child text in the tree. Text is
matched exactly unless you pass a `".*regex.*"`. `back` does not work on iOS.

**The local database has been silently wiped by a container restart.** Re-run
`supabase db reset` before trusting any database result.

**Verify the test before believing the bug.** An "expired token returns 400 not
401" vulnerability turned out to be a token expired by exactly the deliberate
60-second clock skew. The code was right; the test was wrong.

**A green suite proved every online table stopped after hand one.** The engine
parks at HAND_COMPLETE by design so a settlement is never animated over, and
expects the caller to advance. No client command mapped to that, and
`game-command` never called `beginNextHand`. 1,108 tests passed. Fixed with a
`NEXT_HAND` command plus a settlement rest window a timeout can act on.

**`supabase/functions` is excluded from `tsconfig.json`.** Type errors there are
invisible: `PRIVATE_TIMING` was `{bettingSeconds, insuranceSeconds,
actionSeconds}` where `GameTiming` wants milliseconds, so every shared table ran
with **no deadline at all** and RESOLVE_TIMEOUT could never fire.
`assertTimingIsCoherent` now rejects that shape at `createGame`. Treat anything
under `supabase/functions` as unchecked and prove it against the running stack.

**Betting closed on the first player to lock, not the last.** The cascade's
predicate filtered contenders on `originalBet > 0`, so a seat that had not bet
yet was not counted: at a four-seat tournament exactly one stack moved per hand
and everyone slower was dealt out. What stops an absent player stalling a table
is the betting deadline, not that predicate.

**A coverage threshold that matches no files reads as enforcement.** Moving the
strategy module out of `shared/` left `include: ["shared/**"]` no longer matching
it, so its 90% gate passed against zero files and nobody would have noticed. When
you move code, check the gate still points at it — and prove a new gate fails
when breached rather than assuming it works.

**A pgTAP file that counts global rows fails as soon as the feature ships.**
`05_daily_challenge.test.sql` inserted a fixture for `current_date` and collided
the moment `ensure_daily_challenge_for` started creating today's row for real.
Scope fixtures to dates and ids the file owns, and count only its own rows.

**The same applies to integration tests, and it shows up as a flake.** The sprint
tournament test failed once in a hundred-odd runs and passed on retry. The cause
was not timing: registration fills the oldest tournament still short of players,
so a half-filled one left behind by an earlier run SPLIT the test's four players
across two tournaments and neither was dealt. Reproduced deliberately — seed two
leftover entries, watch it fail — then fixed by draining the pool first. Do not
retry a flake until you can reproduce it on purpose.

**A new Edge Function directory without its `deno.json` takes the whole stack
down.** Adding `send-notifications/` made `supabase start` fail with `failed to
read file: open shared/contracts/index.js` and exit with no Functions URL —
which reads as a database or Docker problem, not a missing file in a directory
you just created. The function did not import the contracts itself; it imported
`_shared/command-errors.ts`, which does. Copy the map from an existing function.

**A Maestro loop whose only progress branch is nested inside one state can
deadlock.** `career-node.yaml` tapped "Next hand" inside its betting branch, so
an iteration arriving at a settled hand skipped the whole body — and every
iteration after it did too, because nothing else brings the betting bar back. It
failed intermittently for a year's worth of runs and looked like flakiness. The
fix is structural: check each state at the TOP level of the iteration, so a pass
handles whatever it finds. Diagnosed from the failure's own hierarchy dump, which
showed "Hand 2 of 10" with "Next hand" plainly on screen.

**A tap issued while a screen is settling can be swallowed.** The single
`tapOn: onboarding-guest` occasionally did nothing and the flow then sat on
onboarding until its wait expired — a lost tap that looks like a broken app. All
three flows now tap inside a small `repeat`; once it lands there is nothing left
to tap.

**A test that asserts a place on a GLOBAL leaderboard expires.** "This player is
in the top 100 by weekly XP" held until the local database had a hundred players
with more XP than three hands earn, at which point a correct board failed a
correct test. Same lesson as the pgTAP one above, one layer up: assert the
relationship (`my_leaderboard_position` agrees with the board when the player is
on the page) rather than the position.

**A navigation effect keyed on store state fires for every writer of that
state.** Onboarding's guest path set `completion` and let an effect
`router.replace` to Home; the account buttons set the same state and then
`router.push`ed the auth screen — and the effect fired after commit and
replaced the auth screen with Home, deterministically, on every tap. "Create
Account" looked wired for a whole phase because `every-screen.yaml` asserted
the button was *visible*, not where it led. The effect now checks WHICH
completion it is reacting to. When a screen navigates in two ways, make each
trigger name its own case.

**The app icon and splash do not appear in `npx expo export`.** The export
bundles runtime assets only (the `require()`d PNGs and WAVs). Icon and splash
are consumed by `expo prebuild` into `ios/Arc21/Images.xcassets` and ship in
the native `Assets.car` — verify them with
`assetutil --info <built app>/Assets.car` and by looking at the springboard,
not by grepping the export.

**`textContentType="newPassword"` blocks programmatic typing on the
simulator.** iOS raises the strong-password overlay and Maestro's `inputText`
lands nothing in the field, silently. The sign-IN screen's plain
`textContentType="password"` types fine. Workaround for flows that must fill
the create-account form: `simctl pbcopy` + long-press + "Paste". Fast
`inputText` also drops characters in ordinary fields — paste anything that
must arrive exactly.

**Maestro text matching is case-sensitive against the RENDERED text.** An
overline that uppercases via `textTransform` matches "STRATEGY ACCURACY", not
"Strategy accuracy". Assert on ids or on the exact rendered case.

**Maestro `tapOn` does not scroll.** A title below the fold is present in the
accessibility tree, so `tapOn` "succeeds", taps empty space, and the flow carries
on against an unchanged screen. Use `scrollUntilVisible` first. Also: returning
from a pushed screen sometimes restores the previous scroll position and
sometimes returns to the top, so assert on text that is actually on screen at
that point — and confirm from the failure screenshot rather than guessing, because
an empty view-hierarchy dump means Maestro could not read the tree, not that the
screen was wrong.

**A Maestro failure can be the DRIVER, not the app — and `viewHierarchy` is
where it shows.** THE DECIDING EVIDENCE: `career-node` failed four times in one
session and then passed first time, exit 0, on an idle host — same commit, same
simulator, load average 10.8 instead of 40+. **Maestro needs an idle machine.**
Check `uptime` before you run it and before you believe a failure; below about
load 12 it is reliable, and above 40 the XCUITest runner starts losing view
hierarchy snapshots. It failed four times in phase 14 s2 with
`Request for viewHierarchy failed, code: 500`, or a hang inside
`getHierarchyWithFallback`, at four different points of the flow. Every command
before the failure COMPLETED, and `practice-hand` — which plays a full hand
through the same table components — passed. Before treating that as an app
regression: check `~/.maestro/tests/<run>/xctest_runner_*.log` for
`View hierarchy snapshot` stalling, check `uptime`, kill stale
`maestro-driver-ios` processes, and set
`MAESTRO_DRIVER_STARTUP_TIMEOUT=180000` (which fixes the start-up half of it).
One such failure also ran `xcrun simctl uninstall` for five minutes and left the
app UNINSTALLED — `xcrun simctl get_app_container <udid> com.arc21.app` before
diagnosing anything else, because a missing app reads as a broken flow.

**`create or replace function` silently reverts every LATER redefinition.** Five
functions gained a rate limit this phase, which meant replacing their bodies —
and two had already been redefined by a later migration than the one that
introduced them. Copying the earlier version dropped the `notify_user` call from
`send_friend_request` (six integration tests failed and said so) and the
`expire_stale_rooms()` call from `create_private_room`, which is the entire
content of `20260816130000` — **nothing failed for that one**, and abandoned
lobbies would have started holding their codes for ever again. Before redefining
anything: `grep -l 'create or replace function public.<name>'
supabase/migrations/*.sql` and start from the LAST file.

**A new function's default ACL is `EXECUTE TO PUBLIC`.** So
`grant execute … to authenticated` alone leaves it callable by `anon`, and the
migration reads as if it did not. Sixteen migrations did this, and `anon` could
execute seventeen public functions including all four leaderboards. Always write
the pair:

```sql
revoke execute on function … from public, anon;
grant  execute on function … to authenticated;
```

`public.assert_client_authorization_surface()` now refuses any `public` function
executable by `PUBLIC`, so this fails the migration rather than the audit.

**A migration-time DO block only ever checks the state at its own position in
the ordering.** `20260813121200_hardening.sql` is thirteenth of thirty-two and
had not seen anything applied after it — sixteen migrations of new grants
accumulated behind a gate that had simply stopped being asked. The checks are now
a function called from both the migration and pgTAP; **a migration that changes a
grant should call it as its last line.**

**A rate limit consumed inside the caller's transaction is rolled back by the
caller's exception.** So a limit on an action whose ABUSE path raises charges
nobody: `join_private_room` raising on an unknown code would have given a
code-guesser an unlimited budget, and a boundary test would still have passed. It
returns no row instead, so the attempt commits and counts. Where the limit itself
refuses, raising is correct — a refusal must NOT be recorded, or the window never
drains and the limit becomes a permanent ban.

**PostgREST maps SQLSTATE `PTnnn` to HTTP nnn.** Use `PT429` for a rate-limit
refusal. The username limit raised `55000`, which PostgREST renders as **HTTP
500**: a player who renamed twice in a month was told the server had broken.

**pgTAP's `throws_ok` runs its argument through `EXECUTE`, which refuses
transaction commands.** To assert that a gate fails on a breach, issue the
`savepoint` and the breach OUTSIDE `throws_ok`, then `rollback to savepoint`
after it.

**A new table must have a single-column `uuid` primary key and no float
column.** `00_schema.test.sql` asserts both across the whole schema, so a
`bigint generated always as identity` key or a `real` column fails a suite that
looks unrelated to what you changed.

## Product rules that are easy to get wrong

- Practice is **local and always available** — offline, broke, signed out. It
  never touches the global wallet, XP or leaderboards.
- A career node **always awards its first star for completion**, so bad cards
  can never block progression.
- Private tables use isolated session chips — no global wallet in or out. This
  is anti-collusion design, not a shortcut.
- Tournament decisions are excluded from basic-strategy accuracy, because
  correct tournament play differs from basic strategy. This was once true "by
  construction" because nothing recorded accuracy at all; it is now true by an
  ALLOWLIST — `ACCURACY_ELIGIBLE_MODES` in `_shared/decision-grading.ts` names
  `solo`, `public_table` and `daily_challenge`, so a new mode counts for nothing
  until somebody adds it there on purpose.
- **The daily board's tie-breaks come from the ATTEMPT, not the week bucket.**
  `player_decision_periods` mixes in every ranked decision of the week, so it
  cannot answer "who played this challenge better". `daily_entries` carries its
  own `decisions_total`, `decisions_optimal` and `ev_lost_micros`. EV lost is in
  millionths as a `bigint` — no floating-point column exists in this schema, and
  a float ordering key can rank two identical records differently on two
  machines.
- **Tournament and daily-challenge stacks are a scoring medium.** A sprint's
  10,000 and a challenge's 5,000 never touch a wallet. The only wallet events are
  the 500 entry fee out, and a prize or the daily reward back in — each through
  `apply_wallet_delta` under a key derived from the tournament/challenge and the
  player, never from a client request id.
- **A full sprint is a net SOURCE of 1,500 chips** (2,000 of fees in, 3,500 of
  prizes out), straight from the specification's figures. Deliberate: chips have
  no value and the opening grant is already 25,000.
- One ranked daily attempt per UTC date. A replay is playable and writes **no
  entry row at all**, which is how an unranked run cannot overwrite a ranked
  score — enforced by never writing rather than by comparing.
- Timeouts are predictable and stated: stand, decline insurance. Never silently
  play basic strategy for an absent player.
- Empty states say **why** a surface is empty and never render sample data.
  Statistics shows "no record", not a record of zero.
- **Permission for notifications is asked at a MOMENT, never at onboarding.**
  The four allowed moments are enumerated in `PermissionMoment`: accepting a
  friend request, entering a tournament, opening a private table, or moving the
  switch in Settings. A grant switches on the master preference plus that
  moment's own category and nothing else.
- **The Daily Challenge reminder is scheduled on the device, not pushed.** The
  challenge exists every day for everybody, so a server fan-out would add a row
  per player per day to say something the device already knows. It also makes
  that Settings toggle govern something real.
- **A "your turn" push is written when the server APPLIED A DEFAULT**, not when
  the turn arrives. A fifteen-second action timer is a race a push cannot win;
  what is worth telling somebody is that a hand was played for them. Deduped per
  table, so a player who put their phone down is told once.
- **A loss is never the loudest thing a player hears or the largest thing they
  see.** No red flash, no shake, no sting: `tests/audio` asserts the loss cue is
  quieter than the win, and `OutcomeBadge` gives a halo only to a win.
